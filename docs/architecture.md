# 実装の構成

- `backend/app/db.py`: SQLite、初期マイグレーション、トランザクション。可変の問題構造はJSON payloadとして保存。
- `backend/app/models.py`: 問題・レシピ・生成条件のPydantic検証。
- `backend/app/parser.py`: PyMuPDFによるPDF本文抽出、Excel、PowerPoint、HTML、画像、Tesseract OCR。資料のページ・行・行内文字位置を保持。
- `backend/app/providers.py`: LLMProvider、MockProvider、OpenAIProvider。外部接続はこの境界に集約。OpenAIProviderは選択時に原本PDFをResponses APIのマルチモーダル入力としてページ単位に転記する。生成時には既存問題や直前候補をNGリストとして受け取る。
- `backend/app/question_quality.py`: 本文から定義・規則・条件・因果・比較・数値などの出題候補を抽出し、説明のない見出しや短いラベルだけの範囲を事前に除く。
- `backend/app/generation_quality.py`: ジョブ全体の候補生成予算、棄却理由集計、題材の回避。
- `backend/app/dedupe.py`: 表記を正規化した問題文・解答照合、日本語文字n-gram等による近傍候補検索、使用済みソース範囲の照合。
- `backend/app/main.py`: API、重複・ソース範囲の照合、生成ジョブ、問題編集履歴、完全削除、ローカル利用のオリジン検査、静的ファイル配信。
- `frontend/src/store.ts`: IndexedDB、問題の固定スナップショット、ローカル採点、同期時の削除済み問題の消去。
- `frontend/src/main.tsx`: ダッシュボード、演習、問題バンク、資料、分析。出題レシピ画面は通常のナビから外し、直接生成を主導線にする。
- `frontend/public/sw.js`: 個人APIデータを含まないアプリ画面のキャッシュ。

## データの役割

レシピの `material_ids` で指定した資料から、選択したカテゴリの範囲だけを生成の根拠にします。未指定の既存レシピは後方互換のためカテゴリに一致する全資料を対象にします。テキストを最大4行の範囲へ分け、説明のない見出し・短いラベルだけの範囲は候補から除きます。定義、規則、条件・例外、因果、手順、数値などの事実を抽出し、本文と一緒にモデルへ渡します。未使用範囲を優先して分散しますが、範囲が不足すれば既使用範囲も再利用します。根拠には資料ID、ページ・行、必要な場合は行内の文字位置を保存します。LLMへは本文と不透明な参照キーだけを送り、物理的なページ・行メタデータは問題の題材にしません。既存問題と同じ資料箇所を参照する新しい問いも許可します。

抽出本文は登録時に読みやすい境界で最大12,000文字へ分割し、ページ・行・シート・セル範囲と元チャンクIDを引き継ぎます。Excelセル内の改行は行番号と混ざらないよう空白へ変換し、旧資料では可能な範囲で元の行境界を復元します。旧資料で元の行を安全に特定できない場合は、該当チャンク全体を1つの範囲として扱います。HTML・PowerPoint・OCRの行番号は抽出順の番号として表示します。資料編集で行位置が変わっても、同じページ内に残る根拠本文は既使用範囲として照合します。カテゴリ解析は最大48,000文字、問題生成は最大60,000文字のバッチへ分けます。各問題へ別の未使用行範囲を割り当て、複数回に分けた生成でも既使用範囲を除いて次の候補を選びます。セットには使用済み範囲の位置情報だけを保存するため、問題が削除された後も生成位置を分散できます。問題文・解答はこの履歴に含めません。同一プロセス内の生成は直列化し、保存直前にもSQLiteの書き込みロック内で問題文・解答の完全一致重複を再確認します。

問題生成時には同じ資料に関する既存問題と直前の候補をコンパクトなNGリストとして渡します。NGは同じ問い・答えの再出題を避けるために使い、同じ話題や資料範囲から異なる数値、名称、条件、例外を問う問題は許容します。保存前に形式・指定形式との一致・空欄数・選択肢数・正答露出・完全一致重複・根拠IDを確認します。根拠IDが欠けている場合は自動補完して採用せず、作り直します。

`question_quality.py` の明白なメタ情報・表示上の雑学を除外するルールと、`providers.py` の独立した品質審査を組み合わせます。審査は `learning_value / grounded / clear` が全て合格した場合だけ採用します。簡単な直接想起は有効です。判断の欠損・矛盾・通信障害は品質棄却ではなくAI処理の失敗として扱い、未審査バッチを保存しません。MockProviderは明白な禁止例だけを判定し、意味品質を確認できない旨を表示します。

`generation_quality.py` の予算を全バッチで共有し、候補生成は要求問数の3倍まで、同じ題材の作り直しは最大2回とします。題材自体に価値がない場合は別の範囲へ移ります。棄却済みの題材はジョブ中だけ回避し、使用済み根拠へは登録しません。セットには採用した問題数、要求数、棄却数、終了理由を保存し、0問の空セットは作りません。

問題生成はサーバー側ジョブとして実行します。ジョブの `total/completed` は従来どおり直接生成で問数、レシピ生成でセット数です。共通の `requested_count/accepted_count/rejected_count/attempted_count` と `stage` を追加し、少数・0問の終了には `partial` を使います。目標未達を理由に補充を続けず、`candidate_exhausted` または `attempt_limit` で停止します。最大20問単位またはセット単位で、審査済み問題とセットを一緒に保存します。サーバー再起動では実行中ジョブを失敗へ更新し、保存済み問題は残します。

LANは同じアプリコンテナの8000番をMacの8080番へ公開します。`scripts/deploy-lan.sh` が既存ComposeファイルとPUBLIC_URLを引き継ぎます。アプリ内の書き込みはHostとOriginの一致を検証し、LAN URLからも使えます。HTTPで利用できない `crypto.randomUUID()` には `getRandomValues()` によるUUID生成を用意しています。スマートフォンのナビゲーションに文字ラベルを表示し、生成結果では少数終了と障害を区別します。

## 初期版の制約

- 利用者1人、ローカル環境、単一タブでの編集を想定。認証・クラウド同期は未実装。
- AI生成の意味的な正しさや配点の正確さは保証せず、根拠と警告のレビューを前提とする。
- MockProviderは画面・保存の動作検証用。AIの代替品質は提供しない。
- 標準抽出のPDF本文はPyMuPDFでページ単位・読み順付きに取得し、本文を取得できないページはTesseract OCRにフォールバックする。PDF表はレイアウト文字列、Excel表はセル範囲付きテキスト。PowerPointはスライド内テキストを抽出し、旧形式はLibreOfficeで変換する。スキャンの表セルを厳密に復元する機能はない。
- 公開URLの取得はDNS解決した公開IPへ接続を固定し、転送先も再検証する。資料一覧のAPIは本文を省き、編集画面だけ個別に全文を取得する。
- PDF登録時は標準抽出とLLMマルチモーダル解析を選択できる。後者は文字化け・複雑なレイアウトに有効だが、OpenAI接続、送信コスト、モデルの読み取り誤りがあるため、抽出結果の確認を前提とする。
- サーバー再起動時に未完了ジョブを自動再実行しない。状態を中断へ更新し、保存済みセットは問題バンクから確認できる。
- 編集履歴はAPIで参照可能。専用の差分・ロールバック画面は未実装。
- 問題の削除は物理削除です。編集スナップショットと演習記録から問題本文・該当回答を取り除き、旧ソフト削除データも起動時に消去します。オフライン端末の古いコピーは再接続時の同期で除去します。
- 資料の解析結果編集でversionを進める。原本差し替え時は新しい資料として登録する。
